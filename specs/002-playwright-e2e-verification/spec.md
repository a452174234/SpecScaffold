## 用户场景与测试

### 用户故事 1 — 首页项目列表与导航（优先级：P1）

开发者打开 SpecScaffold Web 应用首页，页面正确加载并展示项目列表。用户可以通过顶部导航或页面内按钮访问新建项目、导入项目等功能入口。当没有任何项目时，系统显示空状态引导。

**优先级理由**: 首页是所有用户流程的起点，导航和项目列表是验证后续功能的前置条件。

**独立测试**: 可通过启动应用、访问首页、验证页面元素可见性和导航跳转来独立测试。

**验收场景**:

1. **给定** 应用已启动，**当** 用户打开首页，**则** 页面标题可见，项目列表区域正确渲染
2. **给定** 数据库中没有项目，**当** 用户打开首页，**则** 显示空状态提示和"新建项目"/"导入项目"入口按钮
3. **给定** 首页已加载，**当** 用户点击"新建项目"按钮，**则** 页面跳转到项目创建页面
4. **给定** 首页已加载，**当** 用户点击"导入项目"按钮，**则** 页面跳转到项目导入页面

---

### 用户故事 2 — 创建脚手架项目（优先级：P1）

开发者通过 Web 界面创建一个新项目，填写项目名称和路径后提交。系统创建项目并跳转到项目详情页，详情页显示项目基本信息和四个功能导航入口（SDD、AI 工作区、任务面板、审计日志）。

**优先级理由**: 项目创建是平台核心入口，创建成功后的详情页是所有后续功能的入口点。

**独立测试**: 可通过创建一个项目并验证列表中出现新项目卡片、详情页渲染正确来独立测试。

**验收场景**:

1. **给定** 用户在项目创建页面，**当** 用户填写项目名称和路径后点击提交，**则** 系统创建项目并跳转到项目详情页
2. **给定** 用户在项目创建页面，**当** 用户未填写必填字段直接提交，**则** 系统显示校验错误提示
3. **给定** 项目创建成功，**当** 用户在详情页查看，**则** 可以看到项目名称、路径、类型等基本信息
4. **给定** 项目创建成功，**当** 用户在详情页查看，**则** 可以看到 SDD、AI 工作区、任务面板、审计日志四个导航卡片

---

### 用户故事 3 — 导入现有项目（优先级：P1）

开发者在导入页面输入本地已有项目的目录路径，系统扫描该目录并展示识别结果（语言、框架），用户确认后完成导入。导入成功后跳转到项目详情页。

**优先级理由**: 导入已有项目与创建新项目同等重要，是用户使用平台的另一核心入口。

**独立测试**: 可通过在文件系统创建一个模拟项目目录（含 package.json 和 tsconfig.json），然后在导入页面输入路径来独立测试。

**验收场景**:

1. **给定** 用户在项目导入页面，**当** 用户输入一个有效的本地项目路径并提交，**则** 系统展示扫描识别结果（语言和框架标签）
2. **给定** 扫描结果已展示，**当** 用户确认导入，**则** 系统创建项目记录并跳转到项目详情页
3. **给定** 用户在项目导入页面，**当** 用户输入一个不存在的路径，**则** 系统显示路径无效的错误提示

---

### 用户故事 4 — SDD 规格驱动开发流程（优先级：P1）

开发者在项目中启动 SDD 流程，通过四步引导界面依次完成功能描述、澄清歧义、生成计划和生成任务。每个步骤完成后自动进入下一步，最终生成的任务可以在任务面板中查看。

**优先级理由**: SDD 是平台的核心方法论，四步引导流程是用户与平台交互最频繁的功能。

**独立测试**: 可通过选择一个项目、进入 SDD 页面、依次完成四个步骤并验证每步 UI 反馈来独立测试。

**验收场景**:

1. **给定** 用户在项目详情页，**当** 用户点击"SDD 规格驱动开发"导航卡片，**则** 页面跳转到 SDD 流程页面，显示四步骤引导
2. **给定** 用户在 SDD 第一步（功能描述），**当** 用户输入功能描述并提交，**则** 系统处理后进入第二步（澄清歧义）
3. **给定** 用户在 SDD 第二步（澄清歧义），**当** 用户输入澄清信息并提交，**则** 系统处理后进入第三步（生成计划）
4. **给定** 用户在 SDD 第三步（生成计划），**当** 用户确认并提交，**则** 系统生成计划并进入第四步（生成任务）
5. **给定** 用户在 SDD 第四步（生成任务），**当** 用户确认并提交，**则** 系统生成任务列表并提示完成

---

### 用户故事 5 — AI 集成工作区操作（优先级：P1）

开发者在 AI 工作区页面选择一个任务，依次使用"生成测试"、"实现代码"、"运行测试"三个操作。每个操作触发后在工作区中显示执行状态和输出日志。

**优先级理由**: AI 工作区是平台与 AI 引擎交互的核心界面，验证其操作可达性至关重要。

**独立测试**: 可通过进入 AI 工作区页面、输入任务 ID、点击操作按钮并验证 UI 反馈来独立测试。

**验收场景**:

1. **给定** 用户在项目详情页，**当** 用户点击"AI 工作区"导航卡片，**则** 页面跳转到 AI 工作区，显示任务 ID 输入框和三个操作按钮
2. **给定** 用户在 AI 工作区，**当** 用户输入任务 ID 并点击"生成测试"，**则** 系统触发操作并在输出区域显示状态
3. **给定** 用户在 AI 工作区，**当** 用户点击"实现代码"，**则** 系统触发操作并在输出区域显示状态
4. **给定** 用户在 AI 工作区，**当** 用户点击"运行测试"，**则** 系统触发操作并在输出区域显示状态
5. **给定** 用户在 AI 工作区，**当** 用户未输入任务 ID 就点击操作按钮，**则** 系统显示输入验证提示

---

### 用户故事 6 — 任务面板状态流转（优先级：P2）

开发者在任务面板查看项目的所有任务列表，每个任务显示当前状态标签。用户可以执行状态流转操作（如从 pending 到 testing），系统验证流转的合法性并更新显示。

**优先级理由**: 任务面板是 TDD 管控的可视化界面，状态流转验证工作流状态机的正确性。

**独立测试**: 可通过创建包含任务的项目、打开任务面板、执行状态变更操作来独立测试。

**验收场景**:

1. **给定** 项目中有已生成的任务，**当** 用户打开任务面板，**则** 以表格形式展示所有任务，每行包含标题、状态标签、优先级
2. **给定** 任务面板已加载，**当** 用户对一个 pending 状态任务执行状态变更操作，**则** 任务状态更新为新状态，标签颜色对应变化
3. **给定** 任务面板已加载，**当** 用户尝试非法的状态跳转（如直接从 pending 到 completed），**则** 系统拒绝操作并显示错误提示

---

### 用户故事 7 — 安全审计日志查看（优先级：P2）

开发者在审计日志页面查看项目的所有安全相关操作记录。每条记录显示工具名、操作、风险级别和审批结果。风险级别和审批结果使用不同颜色标签区分。

**优先级理由**: 审计日志是安全合规的关键功能，需验证页面能正确加载和展示数据。

**独立测试**: 可通过打开审计日志页面、验证表格渲染和标签颜色来独立测试。

**验收场景**:

1. **给定** 用户在项目详情页，**当** 用户点击"审计日志"导航卡片，**则** 页面跳转到审计日志页面，显示日志表格
2. **给定** 审计日志页面已加载且有日志数据，**当** 用户查看日志列表，**则** 每条记录显示工具名、操作、风险级别标签（颜色区分）和审批结果标签
3. **给定** 审计日志数据量较大，**当** 用户滚动或切换分页，**则** 分页控件工作正常

---

### 用户故事 8 — 安全策略查看与更新（优先级：P2）

开发者查看当前项目的安全策略配置，包括高风险工具列表、只读工具列表和危险命令模式。用户可以修改策略并保存更新。当前前端缺少安全策略管理页面，需先补充该页面使其可通过浏览器操作触达。

**优先级理由**: 安全策略管理是安全围栏功能的配置入口，补充前端页面后可通过 E2E 测试验证完整的安全管理闭环。

**独立测试**: 可通过打开安全策略页面、查看当前配置、修改并保存来独立测试。

**验收场景**:

1. **给定** 项目已创建，**当** 用户从项目详情页点击安全策略入口，**则** 页面跳转到安全策略管理页面，显示当前项目的安全策略配置（高风险工具列表、只读工具列表、危险命令模式）
2. **给定** 安全策略页面已加载，**当** 用户修改策略内容并保存，**则** 系统更新策略并显示保存成功提示
3. **给定** 安全策略页面已加载，**当** 用户修改高风险工具列表（添加或移除工具名称），**则** 保存后刷新页面显示更新后的配置

### 边界场景

- 应用未启动时，测试应明确报告连接失败而非超时不报错
- 网络请求失败时（后端未响应），前端页面应显示错误状态而非无限加载
- 并发多个测试场景时，每个测试应使用独立的项目数据互不干扰
- WebSocket 连接断开时，AI 工作区的实时输出区域应优雅降级
- 数据库中无数据时，各页面（任务面板、审计日志）应正确显示空状态

## 需求

### 功能需求

- **FR-001**: 系统必须提供一套完整的 Playwright E2E 测试套件，覆盖首页项目列表的加载和导航功能
- **FR-002**: 系统必须提供项目创建流程的 E2E 测试，包括表单填写、提交、成功跳转和输入校验错误展示
- **FR-003**: 系统必须提供项目导入流程的 E2E 测试，包括路径输入、扫描结果展示和导入确认
- **FR-004**: 系统必须提供 SDD 四步引导流程的 E2E 测试，验证每一步骤的 UI 渲染和步骤切换
- **FR-005**: 系统必须提供 AI 工作区的 E2E 测试，验证任务 ID 输入、三个操作按钮的触发和输出区域的状态变化
- **FR-006**: 系统必须提供任务面板的 E2E 测试，验证任务列表渲染、状态标签颜色和状态流转操作
- **FR-007**: 系统必须提供审计日志页面的 E2E 测试，验证日志表格渲染、风险级别标签和分页功能
- **FR-008**: 系统必须补充安全策略管理前端页面（含路由），并提供该页面的 E2E 测试，验证策略展示和更新保存
- **FR-009**: 每个测试场景必须包含前置数据准备（通过 API 或数据库直接操作），确保测试独立可重复
- **FR-010**: 测试套件必须支持在 CI 环境中运行，使用 headless 浏览器模式
- **FR-011**: 所有页面路由（共 8 个）必须被至少一个测试覆盖，验证页面可达且无 404
- **FR-012**: 测试必须验证前端组件（如代码输出区域、状态标签、工具调用状态指示器）的正确渲染

### 关键实体

- **测试场景 (Test Scenario)**: 对应一个用户故事，包含前置条件、操作步骤和预期结果
- **页面路由 (Page Route)**: 前端的 8 个路由路径，每个路由必须被验证可达
- **测试数据 (Test Fixture)**: 测试前通过 API 或数据库创建的项目、任务、审计日志等数据

## 假设

- 后端服务将在测试启动前自动启动（通过 Playwright 的 webServer 配置或测试 fixture），使用独立的测试数据库
- 测试环境为本地开发环境，不涉及远程部署
- WebSocket 功能的完整验证不在本轮范围内（AI 工作区仅验证 UI 触达性，不验证实际 AI 调用）
- SDD 流程中 Spec Kit 的实际调用不在本轮范围内（仅验证 UI 步骤切换和 API 请求发出）
- 安全围栏的 Hook 端点（/api/audit/evaluate 等）通过 API 测试覆盖，不通过浏览器 UI 触达
- 测试使用 Chromium 浏览器，不覆盖 Firefox 和 WebKit
